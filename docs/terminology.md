# Термины проекта

Документация использует единый словарь:

| В документации | Когда используется |
|---|---|
| проверка | проверка входа, контракта или результата; `validation` сохраняется только в идентификаторах |
| обучающая выборка | MIRACL-RU train и `train_fit` в обычном тексте |
| контрольная выборка | `train_validation` в обычном тексте |
| итоговое оценивание | однократное оценивание на dev после выбора |
| выбор контрольной точки | операция `select-checkpoint` |
| конвейер | последовательность стадий обработки |
| запуск | C1, A1, A2, B1 или выполнение команды |
| артефакт | проверяемый результат стадии; конкретный объект также называется файлом |
| контрольная сумма | SHA-256 файла или состава |
| цифровой отпечаток | составная SHA-256 кода, конфигурации и входов |
| журнал доступа | `dev_access_ledger.jsonl` |
| первичная проверка | короткий обязательный запуск `smoke-finetune` |
| расчёт оценок | применение модели к парам |
| упаковка результатов | создание и проверка ZIP |

Общепринятые названия BM25, cross-encoder, fine-tuning, zero-shot, reranking, paired bootstrap, weak negatives, checkpoint, SHA-256, TREC, CLI, API, GPU, CUDA, Parquet, JSON, Git, GitHub, Kaggle и pytest не переводятся внутри технических контрактов.

Имена файлов, команды, параметры CLI, поля JSON/YAML и идентификаторы Python всегда сохраняются без перевода.
