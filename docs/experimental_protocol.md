# Экспериментальный протокол

## Цель

Проект сравнивает три системы на русскоязычной части MIRACL:

1. BM25;
2. BM25 top-100 с zero-shot reranking;
3. тот же top-100 с reranking после fine-tuning cross-encoder.

Главная проверяемая гипотеза: fine-tuning повышает nDCG@10 относительно сильной zero-shot модели при неизменном множестве кандидатов.

## Неизменяемые входы

- модель: `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`;
- ревизия модели и токенизатора: `1427fd652930e4ba29e8149678df786c240d8825`;
- 100 кандидатов BM25 на запрос;
- train qrels SHA-256: `bf1f737cda0d66bc38fef5f9d91843f7a89428c5c5a8a3dce4764f527ec344ef`;
- основное начальное значение генератора: `20260803`;
- максимальная длина: 320 токенов;
- обрезание: `only_second`;
- точность обучения: `fp32`;
- накопление градиента: 16 запросов.

Документ без экспертной оценки не переобозначается как нерелевантный.

## Разделение train

4 683 обучающих запроса делятся на уровне запросов:

- `train_fit`: 3 976;
- `train_validation`: 707.

Стратификация учитывает число релевантных документов среди кандидатов и наличие экспертно оценённого отрицательного документа. Пересечение частей должно быть пустым. Dev не участвует в разделении и выборе модели.

## Режимы обучения

| Запуск | Режим | Скорость обучения | Эпох |
|---|---|---:|---:|
| C1 | перемешанные метки, `control_c1` | 2e-5 | 1 |
| A1 | `judged_only` | 7e-6 | 3 |
| A2 | `judged_only` | 2e-5 | 3 |
| B1 | `weak_negatives` | лучшая из A1/A2 | 3 |

В `judged_only` используются только экспертно оценённые нерелевантные документы. В `weak_negatives` добавляются неоценённые документы с рангами BM25 26–100. Их вес равен 0,5; ограничения на запрос — 8 экспертно оценённых, 8 слабых и 16 пар суммарно.

Эти значения заданы заранее как консервативные эвристики. Они не считаются найденными оптимумами.

## Функция потерь

Для каждой пары используются оценки положительного и отрицательного документов:

```text
loss = log(1 + exp(-(s_positive - s_negative)))
```

Сначала рассчитывается взвешенное среднее по парам одного запроса, затем точное среднее по окну запросов. Последнее неполное окно нормируется по фактическому числу запросов.

## Контроль и выбор

C1 должен завершиться со статусом `PASS` или `WARN`. `FAIL` и `BLOCKED_FOR_REVIEW` останавливают протокол.

Для каждой эпохи A1, A2 и B1 рассчитывается nDCG@10 на `train_validation`. При равенстве выбирается более ранняя эпоха, затем применяется зафиксированный порядок запусков. Zero-shot S0 остаётся отдельным кандидатом рабочей системы.

Выбор записывается атомарно в `reports/audit/checkpoint_selection.json`. Файл содержит:

- все 10 кандидатов;
- лучшую эпоху каждого запуска;
- выбранную контрольную точку;
- отдельно выбранную рабочую систему;
- SHA-256 метрик и набора кандидатов;
- собственную контрольную сумму `selection_sha256`;
- временную метку UTC.

## Граница dev

Разрешённый порядок:

```text
обучение и внутренняя проверка
→ выбор контрольной точки
→ неизменяемая запись выбора
→ первое событие журнала
→ чтение dev qrels
→ расчёт оценок
→ итоговое оценивание
```

Журнал `dev_access_ledger.jsonl` образует цепочку контрольных сумм. Каждое событие содержит номер, контрольную сумму предыдущего события, `selection_sha256`, SHA-256 контрольной точки и всех dev-входов. Смена любого из этих значений после первого доступа приводит к ошибке.

## Метрики

Основная метрика — nDCG@10 из NIST `trec_eval v9.0.8`. Дополнительно рассчитываются MRR@10, Recall@100, метрики Python для перекрёстной проверки и диагностика разреженной разметки.

Главное сравнение fine-tuned против zero-shot выполняется методом paired bootstrap по 1 252 запросам:

- 10 000 повторных выборок;
- доверительная вероятность 95%;
- порог практической значимости: 0,010;
- начальное значение генератора: `20260802`.

Решение `improvement_confirmed` требует положительной нижней границы интервала и средней разницы не ниже порога.

## Интерпретация weak negatives

Сравнение `judged_only` и `weak_negatives` не является чистым причинным сравнением. B1 одновременно меняет состав отрицательных документов и расширяет число запросов, пригодных для обучения. Результат этого сравнения допускает только описательную интерпретацию.
