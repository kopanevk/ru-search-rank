# Воспроизводимость

## Уровни подтверждения

Проект различает три уровня:

1. локальные тесты кода и контрактов;
2. сквозной запуск на временном наборе данных без настоящего GPU-обучения;
3. полный запуск в Kaggle с моделью, CUDA и официальными данными.

Первые два уровня можно повторить локально. Третий нужен для нового выпуска результатов и не заменяется заглушками.

## Зафиксированное окружение Kaggle

Выпуск v1.0.1 требует:

```text
Python       3.12.13
torch        2.13.0
transformers 5.14.1
tokenizers   0.22.2
```

Полный список находится в `requirements/kaggle.lock`. Notebook не использует `pip install -U`: он устанавливает точные версии без автоматического разрешения незакреплённых зависимостей. Во время упаковки создаётся нормализованный `environment_freeze.txt` без локальных путей и ссылок на редактируемую установку.

Версии основных пакетов доступны в PyPI. Однако наличие пакета не доказывает равенство аппаратной части, CUDA-драйвера и результата обучения; поэтому другой GPU или Python требует отдельного отчёта.

## trec_eval

Путь не зашит в конфигурацию. Разрешение выполняется в порядке:

```text
--trec-eval-path
→ trec_eval_executable
→ TREC_EVAL_PATH
→ PATH
```

Официальное оценивание дополнительно проверяет тег, фиксацию Git, чистоту исходного дерева, SHA-256 Makefile и исполняемого файла, результат `trec_eval -v` и сведения о компиляторе. Известная особенность исходного проекта сохранена явно: выпуск v9.0.8 сообщает строку версии 9.0.7.

## Канонический запуск

Используйте только `scripts/run_finetune_kaggle.ipynb`. Его 24 стадии проверяются `scripts/validate_phase3_notebook.py`. Запуск выполняется через `Restart Kernel and Run All`.

Notebook:

- проверяет GPU, RAM и диск до скачивания весов;
- собирает официальный `trec_eval`;
- проверяет зафиксированное окружение;
- восстанавливает ZIP этапов 1 и 2 без замены существующих байтов;
- получает только train qrels до выбора;
- выполняет тесты и полную первичную проверку;
- запускает C1, A1, A2 и B1 последовательно;
- выбирает контрольную точку ровно в одной логической стадии;
- разрешает dev только после выбора;
- повторно проверяет итоговые ZIP по CRC и SHA-256.

## Схема манифеста v2

`training_manifest.json` содержит:

- имя и версию схемы;
- версию и тег выпуска;
- фактическое и целевое окружение;
- зафиксированный список пакетов;
- ревизию модели;
- контрольные суммы входов, исходного кода и конфигураций;
- отдельное происхождение каждого файла;
- точные сведения C1/A1/A2/B1;
- ограничения, LICENSE и NOTICE.

Поля контрольных сумм имеют явные имена: `file_sha256`, `input_file_sha256`, `training_fingerprint_sha256`. Истории A1, A2 и B1 не могут ссылаться на другой запуск.

## Локальная проверка

```bash
python -m pytest -q
python scripts/validate_phase1_notebook.py
python scripts/validate_phase2_notebook.py
python scripts/validate_phase3_notebook.py
python -m compileall -q src
git diff --check
```

Локальный запуск не доказывает:

- повторяемость оптимизации на другом GPU;
- точное время обучения;
- новую контрольную сумму ZIP v1.0.1;
- численное равенство с официальным запуском без полного применения модели.
